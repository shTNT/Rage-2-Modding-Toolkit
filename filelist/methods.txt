1. HASH ALGORITHM SPECIFICATION
================================================================================

RAGE 2 identifies assets with 64-bit hashes derived from path strings.

Algorithm:      MurmurHash3 x64 128-bit
Input:          path in UTF-8, lowercase, forward slashes, no prefix
Seed:           0
Output used:    h1 (first 64-bit word of the 128-bit digest)

Verified test vectors:

    text/master_eng.stringlookup                                -> 8453EE3581F31F39
    ai/tiles/43_37.navmeshc                                     -> E73A9076A24B7E8D
    terrain/heatwave/patches/width_8/patch_11_00_00.streampatch -> 95C8093796E2DD75

CRITICAL WARNING: The MurmurHash3 variant used by RAGE 2 returns h1
(first 64-bit word) with seed=0. Implementations that use h2, or that
XOR the two halves of the digest, produce 0 matches.

If your hasher gives 0 matches after 1000 attempts, verify with the
test vectors above before assuming your paths are wrong.

2. GAME STRUCTURE AND UNIVERSES
================================================================================

The game ships with TWO complementary archive directories:

    archives_win64/initial/       13 .arc + 13 .tab  (base game, 16,385 hashes)
    archives_win64/supplemental/  33 .arc + 33 .tab  (DLC, 23,134 hashes)

    OVERLAP between universes: 0 hashes
    UNION: 39,519 unique gameplay hashes

There is also a separate localization tree:

    languages/<locale>/game0.tab   3,113 to 37,844 hashes per locale
    Total localization hashes:     45,739

LOCALIZATION IS NOT INCLUDED in this filelist. Reporting coverage that
includes locales inflates the denominator by 2.16x and is misleading
for asset modding purposes.

================================================================================
3. FILELIST FORMAT
================================================================================

Tab-separated format:

    <HEX16>\t<path>

    HEX16 = 16-character uppercase hexadecimal hash
    path  = asset path as understood by the game engine

Example lines:

    8453EE3581F31F39    text/master_eng.stringlookup
    E73A9076A24B7E8D    ai/tiles/43_37.navmeshc

UTF-8 without BOM, LF line endings.

--- 6.2 COMMON TOOL STRUCTURE ---

  Every tool is a standalone C# project with the same skeleton:

    - Reads one or more filelists into a HashSet<ulong> for O(1) lookup
    - Reads the game's .tab files to build the orphan set
    - Runs a self-test: hash("text/master_eng.stringlookup") must equal
      8453EE3581F31F39
    - Generates candidates according to its strategy
    - Uses Parallel.ForEach with Environment.ProcessorCount threads
    - Writes matches to an output file
    - Merges results with existing filelist (dedup by hash)

  All tools use the same Murmur3 implementation: MurmurHash3_x64_128
  with seed=0, taking the low 64 bits of h1.

--- 6.3 MASTERBRUTE - THE WORKHORSE ---

  MasterBrute.exe <tabDir> <filelist> <texturasFull> <rawPaths> <output>

  Phase A: prefix brute (uses neighborhood from filelist)
  Phase B: hash every line of DECA filelist_raw.txt directly
  Phase C: suffix mutation on all known paths

  MasterBruteV3.exe runs 11 fixed iterations in sequence with merge:
    1. identity (raw direct)
    2. lowercase
    3. CapitalizeFirst
    4. CapitalizeTokens
    5. UPPERCASE
    6. numbers 0..999
    7. extension swap (284 matches - biggest single win)
    8. suffix sweep
    9. suffix+numbers
   10. lowercase + numbers
   11. ext swap + suffix sweep

  Iteration 7 alone produced 284 hashes. This was the reason iteration
  exists: the community filelist sometimes has paths with the wrong
  extension.

--- 6.4 RAGE2.EXE TEMPLATE EXTRACTION ---

  Script (PowerShell + .NET) that:
    1. Reads RAGE2.exe into memory
    2. Extracts all ASCII strings >= 6 chars
    3. Filters for strings containing "/" and "%" (format templates)
    4. For each template, replaces %s with known biomas/dirs/assets
       and %d/%02d with numeric ranges
    5. Hashes each generated path against the orphan set

  Templates found: 127, of which 11 have real asset extensions.
  Limited by the fact that only 1 biome ("heatwave") is known.

  Key templates:
    %s/patch_%02d_%02d_%02d.streampatch
    %s/zone_%d/vegetation_%d.bl
    ai/tiles/%d_%d.navmeshc
    textures/atmosphere/tables/irradiance_%s.ddsc
    textures/ui/world_map%s/worldmap_zoom%d/%d.ddsc

--- 6.5 CFX/GFX SCALEFORM PARSER ---

  CFX file format (magic 43 46 58 1F = "CFX\x1F"):
    offset 0x00: magic (4 bytes)
    offset 0x04: u32 uncompressed_size
    offset 0x08: zlib stream

  Parsing algorithm:
    1. Read file, verify magic (0x1F584643 little-endian)
    2. Skip 8-byte header
    3. Decompress remaining bytes as zlib (DeflateStream)
    4. Scan decompressed bytes for printable strings
    5. Filter for strings containing "resources\\ui;" (Perforce paths)
    6. Extract asset references ending in .tgaD (Flash-side name)
    7. Replace .tgaD with .ddsc and hash

  The Perforce paths reveal the original source tree layout:
    D:\Perforce\r2\branch\main\resources\ui;
    {family_code}\{subdir}\{file}.as

  Correct magic is 0x1F (Unit Separator), not 0x20 (space).
  Using the wrong magic byte was the source of a long false-negative
  period before the fix.

--- 6.6 CONTEXTUAL NEIGHBORHOOD ALGORITHM ---

  For each orphan hash in a .tab file:
    1. Find its position in the sorted entry table
    2. Read the 4 neighboring entries (2 before, 2 after)
    3. Extract the directory prefix common to the neighbors
    4. Extract the basename pattern (strip the numeric suffix)
    5. Generate candidates: prefix + common_basename + N + suffix
    6. Hash each candidate

  Rationale: .tab entries are stored in alphabetical order (with some
  exceptions in the multi-block layout), so an orphan between two known
  paths of the same family is statistically likely to belong to that
  family.

  PrefixBruteV2 (51 hashes, 9% holdout validation)
  Sprint5 (51 hashes)

--- 6.7 NUMBER-IN-PATH ALGORITHM ---

  For each known path, find every numeric segment:
    Example: terrain/heatwave/patches/width_8/patch_11_00_00.streampatch
    Numbers: 8, 11, 00, 00

  For each number position, generate variants:
    - +/- 100 keeping the original padding (D2 stays D2)
    - +/- 999 with variable padding (D1, D2, D3, D4)
    - 0..9999 with D2 or D4
    - Double mutation: two numbers at once, +/- 30 each

  Sprint6 phase B produced 282 hashes from this alone.
  Sprint7 phase 2d added 28 more with the double mutation.

--- 6.8 VERIFICATION SCRIPT ---

  The bit-a-bit verification script re-hashes every path in the final
  filelist and checks membership in the .tab files:

    1. For each line "HASH\tPATH":
       - recompute MurmurHash3_x64_128(PATH, seed=0)
       - compare to HASH
    2. Look up HASH in initSet (all hashes from initial .tab files)
       and suppSet (all hashes from supplemental .tab files)
    3. Report OK / mismatch / ghost counts

  Current result: 35,999/35,999 OK, 0 mismatch, 0 ghost.

--- 6.9 MERGE ORDER ---

  Final merge order (later files override earlier):

    1. filelist.txt        (initial, 11,714 entries)
    2. filelist_extra.txt  (initial extras, 2,745 entries)
    3. filelist_supplemental.txt (supplemental, 21,540 entries)

  Dedup is by HASH, not by PATH. The first-seen path for a given hash
  is kept.

7. NEGATIVE FINDINGS / WARNINGS
================================================================================

- The DECA filelist sometimes has paths prefixed with '|'. Always strip
  the prefix or split by [\t| = ;] before hashing. Including the prefix
  has historically caused 0-match runs even for paths that should match.

- The .tab file format (RAGE 2 build 3.1):
      offset 0x00: magic 0x00424154 ('TAB\0')
      offset 0x04: u16 major (3)
      offset 0x06: u16 minor (1)
      offset 0x08: u32 alignment (0x1000)
      offset 0x0C: u32 file_count
      offset 0x10: u32 block_count
      offset 0x14: u32 padding (0)
      offset 0x18: u32 max_compressed_block_size
      offset 0x1C: u32 uncompressed_block_size
      Entry table starts at 0x20 + block_count * 8
      Each entry: 24 bytes
        u64 hash | u32 offset | u32 csize | u32 usize | u16 bIdx | u8 ctype | u8 cflags

  Some third-party parsers assume file_count at 0x1C - this returns 0
  and produces no output.

- Aliases: the same hash can map to multiple paths. Always dedupe by
  HASH, not by PATH, when computing coverage statistics.

- The game has TWO complementary universes (initial + supplemental)
  with ZERO overlap. Tools that only read initial miss 23,134 hashes.

- Localization strings (45,739 unique hashes) are in a separate tree.
  Reporting "coverage" including them doubles the denominator.

- Oodle v7 (oo2core_7_win64.dll) is required to decompress most
  blocks. It is NOT redistributable. Copy from your own game install.

- Scaleform CFX magic is "CFX\x1F" (byte 0x1F), NOT "CFX " (space
  0x20). The wrong magic cost several days of false negatives.

- Windows PowerShell 5.1 cannot compare hex literals greater than
  0x7FFFFFFFFFFFFFFF. Use .ToString('X16') and string comparison.

- Visual Studio Build Tools is only needed for compiling native C++
  hooks. The toolkit itself, the .NET tools, and the Ghidra scripts
  do not require it.
